# 动素抽象与三层架构设计 v1

本设计把一次从接单到物理效果验收的任务，落实到可交换的能力契约、可追溯的身体轨和可核对的控制权。

**评审验收清单**

- [ ] 能从同一目录行追到能力卡、训练动作维和 S0 维持态。
- [ ] 一次取消的请求、接受、停稳及资源处置均能独立核对。
- [ ] S2 校验当前意图与物理效果后才提交进度。
- [ ] 三个系统与外部 Monitor 的控制、信号及阶段简报路径都有明确所有者。
- [ ] W1–W5 能解释并行、纠正、证据遮挡及受保护的恢复。
- [ ] 对照 D1–D11，记录接受、修订或需要实测的依据。

### RH56 手部传感依据

A 为《仿人五指灵巧手 RH56 系列用户手册》V1.0.9（2023-09，PRJ-02-TS-U-001），寄存器地址、空载校零与电流保护见 §1.1、§1.3、§2.2–2.3（通信协议）、§2.4.2（波特率）、§2.4.6–7、§2.4.9、§2.4.12、§2.4.16–17、§2.4.19（状态码）。B 为《仿人五指灵巧手 RH56DFTP 系列用户手册》V1.0.0（2024-12，PRJ-02-TS-U-010），变体差异见 §1.1–1.2、§2.6.16、§2.6.20。2026-11-28 核对了中文资料；用户提供的 2026-09 英文手册链接不可达，未读。[中文手册 A](https://www.inspire-robots.com/d/file/p/2023/11-17/因时机器人仿人五指灵巧手--RH56用户手册V1.09cn%20.pdf) · [中文手册 B](https://www.inspire-robots.com/d/file/p/2025/01-16/因时机器人灵巧手--触觉手用户手册V1.0.0cn.pdf)

厂商 FAQ 将六个压力传感器的位置写为“分别位于每个微型伺服电缸的尾端”。官方文章说明采用力传感器方案，并与传统电流控制作了区分。连杆将负载传到电缸，RH56DFX 传感器读出轴向载荷。物体接触位置或手指构型变化都会改变读数。指端和指腹没有表面传感器，六路信号不能定位触点。[厂商 FAQ](https://www.inspire-robots.com/support/FAQ/dexterous%20hands/) · [厂商文章《灵巧手暗藏玄机，这些关键指标不容忽视》](https://www.inspire-robots.com/news/industry%20news/2024-12-27/247.html)

A 列出 DF 与 BF，未出现型号字符串 DFX。`g1-inspire@3` 暂按 DF 核对寄存器和额定机械参数，具体单元仍待铭牌或厂商确认。

| 项目 | 本体档案采用的硬件事实 |
|---|---|
| 原始反馈 | 只读 `FORCE_ACT(0..5)`（1582–1593）输出 0–1000 的无量纲计数，档案单位为 `count`。依次对应小指、无名指、中指、食指、拇指弯曲和拇指旋转。 |
| 手册表述与有效单位 | A 将数值解释为“指尖提供的握力”，其 g 单位说明不可靠。0.5 N 分辨率也仅为未经本机验证的厂商标称。设计保留原始计数，逐通道标定后才给出 N 估计。 |
| 设定码与机构参数 | `FORCE_SET` 的设置范围为 0–1000，拇指 `DEFAULT_FORCE_SET` 的上电默认范围可到 1500。A 所列 DF 四指／拇指额定握力为 10／15 N，BF 为 4／6 N。这些机构额定值与反馈标定分别登记。 |
| 电流与校零 | `CURRENT(m)` 独立读取六路电缸电流（0–1000 mA），`CURRENT_LIMIT(m)` 执行过流保护。电流推断接触须单独验证。`GESTURE_FORCE_CLB` 在空载、各指均无接触时运行约 6 s，完成设备校零；逐通道计数到 N 的斜率和截距来自独立测力标定。 |
| 通信 | A 使用 RS485 的自定义寄存器协议或 Modbus RTU，默认 115200 bps，可选 57600 或 19200 bps。厂商未给出载荷传感器刷新率。 |
| 触觉变体边界 | 只有触觉型 RH56DFTP 配备指面和掌心阵列。B 列 5–17 个触觉传感器，四根长指各有指端 3×3、指尖 12×8、指腹 10×8，拇指有指端 3×3、指尖 12×8、指中 3×3、指腹 12×8，掌心 8×14。每点用 16 位整数表示，值域 0–4096。B 对其型号另列 −4000 至 4000 的反馈范围和标称分辨率 0.1 N，单独建档。 |

Correll 实验室让手指按压 Shimpo FGV-10XY 测力计，逐通道拟合 `F_est = a × L_raw + b`。以下三项为第三方实测（`THIRD_PARTY_MEASURED`），均满足 R² > 0.98。满码值由拟合式在 `L_raw=1000` 处计算，仅适用于相应测力工况。左右手档案引用同一研究。现场使用 N 阈值前须有覆盖本机、绑定手、通道、模型修订及接触工况的批准记录。[Tan、Xie、Correll，论文第 II 节、表 I](https://arxiv.org/html/2603.08988v1#S2)

| 通道 | a（N/count） | b（N） | R² | 满码估计（N） |
|---|---:|---:|---:|---:|
| 食指 `index` | 0.0075 | −0.414 | 0.987 | 约 7.1 |
| 中指 `middle` | 0.0065 | 0.018 | 0.986 | 约 6.5 |
| 拇指弯曲 `thumb_bend` | 0.0125 | 0.384 | 0.993 | 约 12.9 |

小指、无名指与拇指旋转无已报告拟合。档案标为 `UNCALIBRATED`，现场标定前只用相对空载基线的计数阈值，不赋予 N 满量程。
按 Correll 实验室的第三方时序观测，食指阶跃实验的接口读写循环为 163 Hz，命令发送到首次传感回读约 66 ms。该组高速闭合试验还观察到明显力超调，获取时须在预计接触前减速并保持低速闭合。本机更新率、读回与保护响应时延需分别实测后才能设定预算。[实验条件与图 2](https://arxiv.org/html/2603.08988v1#S2)

### README 与 brief 的冲突裁决

| 主题 | brief 或分析中的提议 | 本轮采用的 README 约束 | 对交付物的影响 |
|---|---|---|---|
| 插件与 S2 | 由插件承担 S2 | Host Adapter + Harness Core + 可替换基础模型组成 S2 | Adapter 仅接单、查询、取消和转发任务事件 |
| Monitor 位置 | 在“底层”运行监测器 | Monitor 在三个系统之外独立观察并主动发信号 | 保护规则在 Monitor，直接送 S0，并向 S2 发 interrupt |
| S2 对身体的调用 | 同时连接 S0 与 S1 | 主技能路径为 S2 ⇄ S1 ⇄ S0；S2 只可直达有界模式 | 直接调用经 Tool Interface 进入 body-modes |
| 核心怎样理解动作 | 把动素贯穿所有组件 | 分类语义属于提供者，Core 读取通用字段 | Resolver 只依赖效果、信息、资源和接续条件 |
| 放手 | 一份分析建议直接切换到开爪模式 | 放手有物理后果，由 S1 执行能力接管维持态 | RL 消费令牌并验证支撑，ModeRequest 的四个动词不含开爪 |

## 系统边界

```text
用户 → Host Adapter → Harness Core S2 ⇄ 基础模型
                         │  ↑
              Invocation │  │ Result / Evidence
                         ↓  │
                     S1 策略服务
                         │  ↑
                   授权目标  实测反馈
                         ↓  │
                     S0 身体控制器 ⇄ 机器人 / 仿真世界

S2 → 外部 Monitor   阶段简报与周期刷新
外部 Monitor ← 用户、身体、世界
外部 Monitor → S0   本地保护请求及原因
外部 Monitor → S2   观测数据、带 interrupt 的 Event
S2 Tool Interface → S0   可选、有界的 ModeRequest
```

| 权限 | 所有者 | 对端能取得的承诺 |
|---|---|---|
| 修订用户目标、拆分子任务 | S2 | goal_revision、子目标效果、当前有效的分支 |
| 在授权子任务内选择局部动作 | S1 | 明确的控制范围、截止时间、结束证据 |
| 准入控制目标、持续稳定身体 | S0 | 当前控制代际、实测状态、每轨处置 |
| 识别保护条件并触发快路径 | 外部 Monitor | 有来源的事件、影响范围、保护关联 ID |
| 判断是否达成用户意图 | S2 Verifier | 可复核的四问、三值结论和证据引用 |

S2 的图按任务事件推进。模型思考期间，Executor 仍可处理取消和对账。
S1 按局部观测更新限时动作块。S0 在自己的本地周期执行稳态与限幅控制。
S2 在阶段开始推送最小意图子句。Monitor 根据当前有效简报核对错物趋近；目标修改权属于 S2。

### 一次调用跨越的边界

1. S2 从机构、对象、用户和能力上下文中构造可验证的子目标。
2. Resolver 绑定提供者、卡片和本体修订，以安装关系检查单次调用，再以真实资源与访问检查并行组合。
3. Executor 冻结 attempt、调用 ID、幂等键、签发时刻和绝对启动截止，再发请求。
4. S1 认证并先比较冻结摘要，重投返回原记录。首次事务持久登记稳定 execution_id 后检查准入，按原 ID 向 S0 申请整组资源。
5. S1 提交带序号及各资源 generation 的短块。S0 在激活时核对截止、保护与依赖，消费块时校验全部写轨。
6. 终态记录实际取得的资源、S0 权威账本和每项唯一处置。实时所有权与停稳证据通过核心查询提供。
7. Verifier 检查新的观测及当前目标版本，决定提交、补证或恢复。
8. Memory 记录这次尝试如何得到结论，供后续复核或修正。

### 一次保护跨越的边界

1. Monitor 的规则命中，将受影响资源和保护级别送到 S0。
2. S0 立即停止接收旧代际指令，在耦合范围内维持支撑与必要接触。
3. Monitor 发出独立 interrupt，关联事件及可用的保护回执。
4. S2 隔离待派发的旧分支，向已派发的调用请求取消。
5. 实测稳定并核对全部处置后决定恢复。停稳故障可报 FAILED + ACCEPTED，未结清的资源持续隔离，已独立结清的处置保留。
6. 每个锁存原因和作用范围跨重启保存，分别要求 Monitor 匹配解除与 S0 本地检查。恢复记录不完整时继续启动封锁。

## 从语义追到实物

以右手把杯子送到架子为例，四个派生产物可以逐一对照。

| 问题 | 使用的数据 | 具体结论 |
|---|---|---|
| S2 能委派什么 | 动素目录的 temporal_form、层、能力模板 | 选择搬运能力，参数绑定杯、目的地和已有握持 |
| 策略能写哪里 | 选定右侧、可选腰和实际 grant | RA 激活，可选 W；RH 的手指不进入动作损失 |
| 此阶段监测什么 | 目录的 monitoring 与当前调用绑定 | 核对持物手的滑移和载荷移动走廊 |
| 身体必须保持什么 | 目录的 maintained 和 state_left | RH 保持 RETENTION，L 维持 BALANCE |
| 到架子后谁接管 | S0 实测、维持令牌、后继入口条件 | S1 的放置子任务在支撑就绪后接管手部 |
| 怎样知道完成 | 当前身份、支撑、脱手和目标版本 | 所有必要谓词成立时才提交进度 |

历史 Hold 描述物体静止时的握持。
机器人 Simo 轨在搬运期间也记录 `RH:H(owner=S0)`，同时记录 `RA:TL(owner=S1)`。
这处语义扩展使“物体在动，手指仍由本地控制器负责”能被训练与运行日志共同表达。

`E` 是头部相机观察轨。G1 没有主动颈关节。
主动变更观察方向要申领 `W` 或 `L`，并考虑对其他活动分支视野的影响。
RH56DFX 的每手六个驱动器与 G1 的 29 个本体自由度分别登记。`g1-inspire@3` 为每只手发布六路轴向载荷计数和独立电流通道，指面触觉阵列不可用。腕部相机仍待确认。[身体示例](../../vla-harness/contracts/v1/examples/body-profile.g1-inspire.json)

### 三类容易混淆的记录

| 记录 | 创建者 | 可用于哪个决策 |
|---|---|---|
| 已经取得过对象的事件 | S1 或 Monitor | 恢复历史和定位交接时刻 |
| 当前仍然保持对象的实测 | S0 伴随来源和时刻 | 后继能否依赖保持或消费令牌 |
| 这次拿到的是用户指定对象 | S2 Verifier | 已验证的任务进度 |

调用超时只改变 S2 的可知状态。
控制器的本地期限到达时，身体转入适当兜底，保留必要握持与平衡。
S2 确认旧调用无法继续产生冲突指令，再按实测结果选择后续操作。

### 三仓之间的版本关系

- 总仓记录设计评审结论、复现场景及跨层依赖。
- 策略仓的 catalog revision 决定标注码、能力资源与动作掩码的来源。
- 协议独立版本化，双方验证协商形状。HTTP 操作首次绑定到 `openapi.yaml` 并正式发布前，`1.0.0` 是可原位修订的草案。发布后新增字段须协商新 minor；依赖新版身体元数据的能力不向旧形状的对端派发。
- BodyProfile revision 决定抽象资源到轴、传感器和控制模式的映射。
- 推理模型版本与 capability revision 都随执行记录保留。
- 对账或轨迹回收时必须能找到当时的版本，避免用新目录重解释旧动作。

### D1 · 事件和保护通道

推荐在统一契约中共享时间、来源、范围和证据类型。
将事件作为核心执行 API 的必选部分会增加独立策略服务的接入成本。
独立事件协议能单独演进，但要再维护跨版本关联。
评审依据是两个观察客户端能否按游标补放并识别同一保护事件。

### D2 · 有界模式请求

四个动词为 HOLD、SLOW、STOP、SWITCH_PROFILE。
把模式伪装成普通技能会混淆实际应用回执和策略执行结果。
私有控制器 ABI 便于适配单设备，替换身体的成本较高。
由 S0 作最终准入，动作执行继续走 S1 契约。

### D3 · 可选预测

预测返回有单位、参考系与有效窗的动作数据。
强制所有执行提供者同时实现预测，会增加纯程序技能的接入负担。
完全私有的预测便于缩小初版范围，但难以跨客户端回放。
验收时核查预测请求没有产生 drive grant 或目标流。

### D4 · 正交状态

同一条记录可以同时表达“已受理取消、仍在停稳、效果未知”。
单一扁平枚举会把通道超时和物理失败压进同一状态。
任意提供者自定义全部状态则难以安全互通。
细节通过命名空间 reason code 补充，核心转换见[协议设计](../../vla-harness/docs/protocol-v1.md)。

### D5 · 上下文边界

S2 写入有来源、时间、可修订范围的任务与会话记忆。
S1 按调用读取目标、当前观测和必要引用。
共享整个存储减少传参，却把实现绑定到同一世界模型。
耐久幂等记录与控制回执由执行端持有，和跨任务策略记忆分别管理。

### D6 · 控制授权

S0 按轨做原子准入，检查同轴别名、耦合域和实际支持状态。
全身串行很容易审计，但会阻塞抽屉任务中可验证的独立工作。
由每个策略各自仲裁，多个服务可能同时认领同一实体轴。
评审时重点复核取消后持续握持、旧块重放和共享腰部竞争。

### D7 · 词表演进

腿部策略通过 `x.locomote` 接入，Simo 标签用 `LO`。
注视通过 SH 加上改变视角的实际驱动轨表达。
双手传递以给予侧 RL 和接取侧 G 的重叠区间表达。
只有留出数据表明当前表达无法区分重要动作分布，才考虑增加新行。

### D8 · 创建回执丢失

推荐核心回查返回 PENDING、REJECTED、ADMITTED 或 ABSENT，以及可授权读取的 S0 实测与所有权。有执行句柄时再读原执行。
备选是重放同键创建。幂等查重先于任何现场前置条件，保留原截止。ABSENT 只有在截止已过、重新读取的权威账本覆盖原窗口且核对了旧授权后，才足以排除晚启动。

### D9 · 阶段监测简报

**设计中。** 推荐在可派发阶段开始时由 S2 单向推送类型化租约简报。观测数据继续供给 S2，需要重新评估时才发带 interrupt 的 Event。基线独立运行，周期刷新补偿丢包；必需子句确定失败或超过批准宽限时先收紧再中断；S2 对账后按原因决定是否可重派，S0 在 Monitor 心跳失联时按身体策略降级。连续丢包期间只剩基线，S2 无法获知空窗长度。

| 议题 | 备选与取舍 |
|---|---|
| 意图形状 | 预批准 profile ID 加参数可缩小报文，但组合和部分支持难表述，适合登记表之下的实现。固定 invocation 投影片段只适合简单拾放，保留为迁移思路。 |
| 送达 | 单次推送最简单，首发丢失或 Monitor 重启后整个阶段会缺意图；推荐存活时固定周期刷新。 |
| 事件边界 | 取消无需中断的事件会遗漏普通指令和世界事实，或迫使它们触发复核；推荐以派生观测共享持久游标。 |
| 逐子句确认 | 不采纳派发等待布防或 S0 核验布防凭证：会增加自身状态回传、耦合执行活性、把曾布防误读为受保护，还需跟踪实例、修订与陈旧回执。必需覆盖失败已有本地收紧与中断路径。 |
| 语义上限 | 仅允许 SLOW 更保守，但错物接触可能需保持；推荐经规则层确认最多 SOFT_HOLD。 |
| 人员交接 | 可暂不支持近人操作；推荐预先独立批准操作 profile，经 SWITCH_PROFILE 受理后仅可进一步收紧。当前档案未授权。 |

待议：语义层做任务理解时是否需要预期效果等阶段意图。本轮用子句和可选 capability_ref 表达，不新增 intent 块。

基线规则采用 `baseline/<name>@<major>`。仅无任何本地阶段记录且无已知执行时允许双空中断；保留期内的到期阶段仍用 phase_contexts 定位，意图 UNKNOWN。S2 依据 S0 回执的实际保护范围隔离待派项。

到期静默回到 BASELINE，保留期内有效续租重装。曾 ARMED 而输入消失记 LOST；从未布防且原宽限耗尽即 GRACE_EXPIRED。回收推进本次启动内的签发时间水位，无记录且早于水位的简报在本次启动内不能重新取得宽限。

残余风险：Monitor 重启以投递 sent_at 与本地启动时刻的误差界建立启动围栏，不持久化 END／REVOKE。误差带内的重启前迟到包仍可能通过；撤销丢失的旧意图受租约限制。本次 Monitor 启动内，水位可阻止已被回收的存活阶段恢复，也可能因较晚签发阶段先被回收而挡住较早签发、从未送达的存活阶段。两者在本次启动内只剩基线；重启清空水位后，任何仍存活的阶段可由合格的新鲜刷新重新安装，建立新的本地布防历史。

### D10 · 保护等级

SLOW 限制速度，SOFT_HOLD 暂停冲突目标并保持当前约束。
S2 对账且 S0 重新准入后，新的有效派发可取代这两档软保护。
STOP_LATCHED 的每个原因均有自己的记录和范围，须匹配 Monitor 解除及 S0 本地检查。重启时控制与保护 epoch 均取持久高水位之后的新值。
控制器按资源隔离受影响旧授权，恢复动作重新受理。

### D11 · 身体控制实现归属

置于策略仓的 `environments/` 便于在同一适配层试验仿真与真机。
独立 S0 组件便于跨策略服务共享仲裁、控制生命周期和硬件适配。
代码位置不影响 S0 的最终控制权与 Monitor 本地保护路径。
评审时比较设备适配复用、独立部署需求与故障隔离成本。

### D12 · 跨层架构检验场景集

**设计中。** 推荐由总仓持有八个详例、十二个表例，Markdown 用于审阅，由同一份 YAML 和 schema 约束机读输入。新增场景补基线、故障、授权、两种表达和三张矩阵；B 档成为测试目标后升为 A 档。按可表达、小修和架构变更分流；小修留清单，三项控制部署选择（其中一项涉及条件性架构变更）[待用户裁决](scenarios/gaps.md#待裁决的控制边界)，监测需求的五项反馈中，阶段意图问题回流 D9 待裁决。

| 备选 | 取舍 |
|---|---|
| 只写 Markdown | 初始成本低，悬空节点、缺判据和覆盖遗漏较难机械发现。 |
| 放在策略提供者仓 | 训练导出方便，但提供者需维护上层恢复语义与跨仓验证。 |
| 全部扩为详例 | 每例检验更深，评审成本也更高；表例先保留任务广度。 |

## 评审顺序与证据

### 第一轮 · 核对符号与约束

1. 比较 YAML 目录与属性表的码、主时间形态、主实施层和资源访问。
2. 在 G、TL、RL 三行间跟踪手部状态，找出谁能消费令牌。
3. 查验所有物理对象和空间量的来源、采集时刻、单位和参考系。
4. 选择一个第三方策略，检查它是否能仅依靠通用字段描述能力。
5. 对照 D1–D11 标出必须写入下一版契约的决定。

### 第二轮 · 检查五条轨迹

1. W1 核对每个动作边界以及进入下一能力需要的物理证据。
2. W2 同时处理用户修改、接触身份不明和取消响应丢失。
3. W3 验证屏障前左右臂并发、腰轨 `W` 的授权时机和抽屉稳定性。
4. W4 核对双手的相对姿态和双方持续握持的运行时所有者。
5. W5 核对步态遇障时保护作用域和上身继续执行所需条件。

### 第三轮 · 协议复核

- 同键同内容返回已有回执；同键异内容构成冲突。
- 终态绑定实际 Result；本地结束与上层效果验证分别可查。
- 旧 scope、generation 或 protection epoch 的指令不再具备写权。
- 观察不足时能保留 UNKNOWN，补证后由新 Verification 修订。
- 客户端失联期间，身体的局部保护及维持态仍有责任主体。

### 后续实测的入口条件

本轮的结构检查能够验证字段、引用、对象约束和资料一致性。
停止距离、滑移补偿能力以及保护延迟需要在后续受控实验中测量。
首批试验宜先在声明的 Isaac Sim 6.2 / Isaac Lab 3.0 本体配置中回放。
真机需核对具体型号与寄存器配置。按手校零、按通道和工况核验或补测计数到 N 的模型，并测量本机读写、命令响应及低速闭合时的载荷超调。
策略比较以 openpi π0.5 为基线，Isaac-GR00T N1.7 为备选。
训练、数据准备、控制实现和运行时契约测试属于后续阶段。

设计评审的产出应包括各项裁决、适用版本、负责组件和可复查的证据。
任何实测通过或模型收益均应随相应实验记录单独登记。
