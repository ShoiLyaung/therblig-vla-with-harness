# 动素抽象与三层架构设计 v1

本设计把一次从接单到物理效果验收的任务，落实到可交换的能力契约、可追溯的身体轨和可核对的控制权。

**评审验收清单**

- [ ] 能从同一目录行追到能力卡、训练动作维和 S0 维持态。
- [ ] 一次取消的请求、接受、停稳及资源处置均能独立核对。
- [ ] S2 校验当前意图与物理效果后才提交进度。
- [ ] 三个系统与外部 Monitor 的四条控制／信号路径都有明确所有者。
- [ ] W1–W5 能解释并行、纠正、证据遮挡及受保护的恢复。
- [ ] 对照 D1–D11，记录接受、修订或需要实测的依据。

### 事实依据

1. 已定的仓库职责、调用方向、控制权和观测要求见[总仓架构](../../README.md)。
2. 任务范围、硬件配置和训练分工的动机见[原始意图](../brief.md)。
3. Ferguson 汇编了 Gilbreth、Mogensen 和 Barnes 的定义。历史起止以汇编原文为依据。[原文 PDF](https://web.mit.edu/allanmc/www/Therblgs.pdf)
4. S2、执行契约和监测快路径的依据来自 Fig. 3 与 §2–3。[论文 v1](https://arxiv.org/html/2611.18359v1)
5. 两份分析报告补足建模和训练细节；具体设计采用本轮计划裁决。

Ferguson 按每只手分别绘制 Simo 轨，使用脚操作时也单独记录。
这里借用了同一时间轴上的独立占用思想。
机械构型、模型切段、动作掩码、保护边界均属本设计补充。

论文给出分层职责、基于证据的验证和取消阶段。
论文没有提供 Monitor 的实测时延，也没有规定抽屉任务应如何锁定身体。
W1–W5 的消息、时间边界和资源组合都是评审用的设计轨迹。

### README 与 brief 的冲突裁决

| 主题 | brief 或分析中的提议 | 本轮采用的 README 约束 | 对交付物的影响 |
|---|---|---|---|
| 插件与 S2 | 由插件承担 S2 | Host Adapter + Harness Core + 可替换基础模型组成 S2 | Adapter 仅接单、查询、取消和转发任务事件 |
| Monitor 位置 | 在“底层”运行监测器 | Monitor 在三个系统之外独立观察并主动发信号 | 保护规则在 Monitor，直接送 S0，并向 S2 发 interrupt |
| S2 对身体的调用 | 同时连接 S0 与 S1 | 主技能路径为 S2 ⇄ S1 ⇄ S0；S2 只可直达有界模式 | 直接调用经 Tool Interface 进入 body-modes |
| 核心怎样理解动作 | 把动素贯穿所有组件 | 分类语义属于提供者，Core 读取通用字段 | Resolver 只依赖效果、信息、资源和接续条件 |
| 放手 | 一份分析建议直接切换到开爪模式 | 放手有物理后果，由 S1 执行能力接管维持态 | RL 消费令牌并验证支撑，ModeRequest 的四个动词不含开爪 |

## 系统边界

```text
用户 → Host Adapter → Harness Core S2 ⇄ 基础模型
                         │  ↑
              Invocation │  │ Result / Evidence
                         ↓  │
                     S1 策略服务
                         │  ↑
                   授权目标  实测反馈
                         ↓  │
                     S0 身体控制器 ⇄ 机器人 / 仿真世界

外部 Monitor ← 用户、身体、世界
外部 Monitor → S0   本地保护请求及原因
外部 Monitor → S2   状态、事件、interrupt
S2 Tool Interface → S0   可选、有界的 ModeRequest
```

| 权限 | 所有者 | 对端能取得的承诺 |
|---|---|---|
| 修订用户目标、拆分子任务 | S2 | goal_revision、子目标效果、当前有效的分支 |
| 在授权子任务内选择局部动作 | S1 | 明确的控制范围、截止时间、结束证据 |
| 准入控制目标、持续稳定身体 | S0 | 当前控制代际、实测状态、每轨处置 |
| 识别保护条件并触发快路径 | 外部 Monitor | 有来源的事件、影响范围、保护关联 ID |
| 判断是否达成用户意图 | S2 Verifier | 可复核的四问、三值结论和证据引用 |

S2 的图按任务事件推进。模型思考期间，Executor 仍可处理取消和对账。
S1 按局部观测更新限时动作块。S0 在自己的本地周期执行稳态与限幅控制。
Monitor 订阅活动调用以发现“当前正在接近错误对象”；目标修改权属于 S2。

### 一次调用跨越的边界

1. S2 从机构、对象、用户和能力上下文中构造可验证的子目标。
2. Resolver 绑定提供者、卡片和本体修订，以安装关系检查单次调用，再以真实资源与访问检查并行组合。
3. Executor 冻结 attempt、调用 ID、幂等键、签发时刻和绝对启动截止，再发请求。
4. S1 认证并先比较冻结摘要，重投返回原记录。首次事务持久登记稳定 execution_id 后检查准入，按原 ID 向 S0 申请整组资源。
5. S1 提交带序号及各资源 generation 的短块。S0 在激活时核对截止、保护与依赖，消费块时校验全部写轨。
6. 终态记录实际取得的资源、S0 权威账本和每项唯一处置。实时所有权与停稳证据通过核心查询提供。
7. Verifier 检查新的观测及当前目标版本，决定提交、补证或恢复。
8. Memory 记录这次尝试如何得到结论，供后续复核或修正。

### 一次保护跨越的边界

1. Monitor 的规则命中，将受影响资源和保护级别送到 S0。
2. S0 立即停止接收旧代际指令，在耦合范围内维持支撑与必要接触。
3. Monitor 发出独立 interrupt，关联事件及可用的保护回执。
4. S2 隔离待派发的旧分支，向已派发的调用请求取消。
5. 实测稳定并核对全部处置后决定恢复。停稳故障可报 FAILED + ACCEPTED，未结清的资源持续隔离，已独立结清的处置保留。
6. 每个锁存原因和作用范围跨重启保存，分别要求 Monitor 匹配解除与 S0 本地检查。恢复记录不完整时继续启动封锁。

## 从语义追到实物

以右手把杯子送到架子为例，三个派生产物可以逐一对照。

| 问题 | 使用的数据 | 具体结论 |
|---|---|---|
| S2 能委派什么 | 动素目录的 temporal_form、层、能力模板 | 选择搬运能力，参数绑定杯、目的地和已有握持 |
| 策略能写哪里 | 选定右侧、可选腰和实际 grant | RA 激活，可选 W；RH 的手指不进入动作损失 |
| 身体必须保持什么 | 目录的 maintained 和 state_left | RH 保持 RETENTION，L 维持 BALANCE |
| 到架子后谁接管 | S0 实测、维持令牌、后继入口条件 | S1 的放置子任务在支撑就绪后接管手部 |
| 怎样知道完成 | 当前身份、支撑、脱手和目标版本 | 所有必要谓词成立时才提交进度 |

历史 Hold 描述物体静止时的握持。
机器人 Simo 轨在搬运期间也记录 `RH:H(owner=S0)`，同时记录 `RA:TL(owner=S1)`。
这处语义扩展使“物体在动，手指仍由本地控制器负责”能被训练与运行日志共同表达。

`E` 是头部相机观察轨。G1 没有主动颈关节。
主动变更观察方向要申领 `W` 或 `L`，并考虑对其他活动分支视野的影响。
RH56DFX 的每手六个驱动器与 G1 的 29 个本体自由度分别登记。
触觉和力传感能力以设备实例 profile 为准。[身体示例](../../vla-harness/contracts/v1/examples/body-profile.g1-inspire.json)

### 三类容易混淆的记录

| 记录 | 创建者 | 可用于哪个决策 |
|---|---|---|
| 已经取得过对象的事件 | S1 或 Monitor | 恢复历史和定位交接时刻 |
| 当前仍然保持对象的实测 | S0 伴随来源和时刻 | 后继能否依赖保持或消费令牌 |
| 这次拿到的是用户指定对象 | S2 Verifier | 已验证的任务进度 |

调用超时只改变 S2 的可知状态。
控制器的本地期限到达时，身体转入适当兜底，保留必要握持与平衡。
S2 确认旧调用无法继续产生冲突指令，再按实测结果选择后续操作。

### 三仓之间的版本关系

- 总仓记录设计评审结论、复现场景及跨层依赖。
- 策略仓的 catalog revision 决定标注码、能力资源与动作掩码的来源。
- 协议独立版本化，两个实现引用同版 schema 和 examples。
- BodyProfile revision 决定抽象资源到轴、传感器和控制模式的映射。
- 推理模型版本与 capability revision 都随执行记录保留。
- 对账或轨迹回收时必须能找到当时的版本，避免用新目录重解释旧动作。

### D1 · 事件和保护通道

推荐在统一契约中共享时间、来源、范围和证据类型。
将事件作为核心执行 API 的必选部分会增加独立策略服务的接入成本。
独立事件协议能单独演进，但要再维护跨版本关联。
评审依据是两个观察客户端能否按游标补放并识别同一保护事件。

### D2 · 有界模式请求

四个动词为 HOLD、SLOW、STOP、SWITCH_PROFILE。
把模式伪装成普通技能会混淆实际应用回执和策略执行结果。
私有控制器 ABI 便于适配单设备，替换身体的成本较高。
由 S0 作最终准入，动作执行继续走 S1 契约。

### D3 · 可选预测

预测返回有单位、参考系与有效窗的动作数据。
强制所有执行提供者同时实现预测，会增加纯程序技能的接入负担。
完全私有的预测便于缩小初版范围，但难以跨客户端回放。
验收时核查预测请求没有产生 drive grant 或目标流。

### D4 · 正交状态

同一条记录可以同时表达“已受理取消、仍在停稳、效果未知”。
单一扁平枚举会把通道超时和物理失败压进同一状态。
任意提供者自定义全部状态则难以安全互通。
细节通过命名空间 reason code 补充，核心转换见[协议设计](../../vla-harness/docs/protocol-v1.md)。

### D5 · 上下文边界

S2 写入有来源、时间、可修订范围的任务与会话记忆。
S1 按调用读取目标、当前观测和必要引用。
共享整个存储减少传参，却把实现绑定到同一世界模型。
耐久幂等记录与控制回执由执行端持有，和跨任务策略记忆分别管理。

### D6 · 控制授权

S0 按轨做原子准入，检查同轴别名、耦合域和实际支持状态。
全身串行很容易审计，但会阻塞抽屉任务中可验证的独立工作。
由每个策略各自仲裁，多个服务可能同时认领同一实体轴。
评审时重点复核取消后持续握持、旧块重放和共享腰部竞争。

### D7 · 词表演进

腿部策略通过 `x.locomote` 接入，Simo 标签用 `LO`。
注视通过 SH 加上改变视角的实际驱动轨表达。
双手传递以给予侧 RL 和接取侧 G 的重叠区间表达。
只有留出数据表明当前表达无法区分重要动作分布，才考虑增加新行。

### D8 · 创建回执丢失

推荐核心回查返回 PENDING、REJECTED、ADMITTED 或 ABSENT，以及可授权读取的 S0 实测与所有权。有执行句柄时再读原执行。
备选是重放同键创建。幂等查重先于任何现场前置条件，保留原截止。ABSENT 只有在截止已过、重新读取的权威账本覆盖原窗口且核对了旧授权后，才足以排除晚启动。

### D9 · 活动意图订阅

Monitor 接收实体锚定、禁选对象、活动轨、版本与有效期。
通过主动调用获取意图会引入轮询时序与网络依赖。
复制整个任务上下文会扩大暴露面，陈旧意图也更难发现。
订阅中断时保留确定性保护，语义判断报告缺少意图依据。

### D10 · 保护等级

SLOW 限制速度，SOFT_HOLD 暂停冲突目标并保持当前约束。
S2 对账且 S0 重新准入后，新的有效派发可取代这两档软保护。
STOP_LATCHED 的每个原因均有自己的记录和范围，须匹配 Monitor 解除及 S0 本地检查。重启时控制与保护 epoch 均取持久高水位之后的新值。
控制器按资源隔离受影响旧授权，恢复动作重新受理。

### D11 · 身体控制实现归属

置于策略仓的 `environments/` 便于在同一适配层试验仿真与真机。
独立 S0 组件便于跨策略服务共享仲裁、控制生命周期和硬件适配。
代码位置不影响 S0 的最终控制权与 Monitor 本地保护路径。
评审时比较设备适配复用、独立部署需求与故障隔离成本。

## 评审顺序与证据

### 第一轮 · 核对符号与约束

1. 比较 YAML 目录与属性表的码、主时间形态、主实施层和资源访问。
2. 在 G、TL、RL 三行间跟踪手部状态，找出谁能消费令牌。
3. 查验所有物理对象和空间量的来源、采集时刻、单位和参考系。
4. 选择一个第三方策略，检查它是否能仅依靠通用字段描述能力。
5. 对照 D1–D11 标出必须写入下一版契约的决定。

### 第二轮 · 检查五条轨迹

1. W1 核对每个动作边界以及进入下一能力需要的物理证据。
2. W2 同时处理用户修改、接触身份不明和取消响应丢失。
3. W3 验证屏障前左右臂并发、腰轨 `W` 的授权时机和抽屉稳定性。
4. W4 核对双手的相对姿态和双方持续握持的运行时所有者。
5. W5 核对步态遇障时保护作用域和上身继续执行所需条件。

### 第三轮 · 协议复核

- 同键同内容返回已有回执；同键异内容构成冲突。
- 终态绑定实际 Result；本地结束与上层效果验证分别可查。
- 旧 scope、generation 或 protection epoch 的指令不再具备写权。
- 观察不足时能保留 UNKNOWN，补证后由新 Verification 修订。
- 客户端失联期间，身体的局部保护及维持态仍有责任主体。

### 后续实测的入口条件

本轮的结构检查能够验证字段、引用、对象约束和资料一致性。
停止距离、滑移补偿能力以及保护延迟需要在后续受控实验中测量。
首批试验宜先在声明的 Isaac Sim 6.2 / Isaac Lab 3.0 本体配置中回放。
真机的 RH56DFX 传感器配置、安装标定和允许的包络需要实物核实。
策略比较以 openpi π0.5 为基线，Isaac-GR00T N1.7 为备选。
训练、数据准备、控制实现和运行时契约测试属于后续阶段。

设计评审的产出应包括各项裁决、适用版本、负责组件和可复查的证据。
任何实测通过或模型收益均应随相应实验记录单独登记。
