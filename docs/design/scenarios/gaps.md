## 待裁决的控制边界

三个部署决策保留待裁决。只有 C02 在所列的跨提供者部署约束下归入架构变更。此轮没有提出公共 schema 修改；以下区分当前可观察记录、现有可行替代和真正会排除替代的条件。

- **C01 · 材料力限。** 相同手和通道面对两种材料，可以发现两张固定卡，分别绑定不同的批准 profile；Invocation.safety、实际配置、保持令牌及 S0 处置可追溯到不同工况。当前未验证的是本机限值与接管后持续生效。只有部署要求在未能预枚举的材料工况间在线选择限值，才排除预装固定配置；若必须在每个控制周期由 S0 强制执行，上层检测或事后中断也不满足要求。决定是否承担这项能力前，先做材料与执行器验证。
- **C02 · 动态支撑。** 单个全身 composite 可以在同一本地控制边界封锁失效动作，稳定后串行可以使用现有 RELEASED、支撑谓词与重新准入。只有任务同时要求重叠运动、两套提供者独立受理／取消且任一侧失败须就地封锁另一侧排队块，才同时排除这两条替代。独立执行的两张卡、两份 Invocation、Execution.leases、当前 owner、维持令牌及 Result 反映各自授权与结果；周期查询观察到 RUNNING 或稍后看到终态都不能提供控制周期内的原子封锁。待裁决的是 S0 本地跨执行依赖的行为及验证，不将采样不足直接归为报文字段缺失。
- **C03 · 近人配置。** 通用 APPLIED 只有在结合准确的 profile_id／修订、实际范围、局部实测、批准的人体区域、匹配规则及独立承重证据后才有交接含义。封闭部署能共同验证这些前提；当前档案缺这套批准，明确拒绝即可。仅当要求独立更新控制／监测配置且不停机重配，才排除预装同版域；若现场必须完成交接，则始终拒绝不满足功能要求。先裁决部署约束及本地联锁，不把配置缺失视为新协议的反例。
