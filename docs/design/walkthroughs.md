# 跨层走通示例

本文用五个任务推演 S2、S1、S0 与 Monitor 的消息、分轨授权和效果验证。

## 验收清单

- [ ] W1 覆盖搜索、绑定、空手移动、获取、搬运、摆位、释放与回撤。
- [ ] W2 展示直接保护、活动调用中断、丢失取消回执后的按句柄对账，以及两种恢复分支。
- [ ] W3 展示两臂并发、腰资源约束、显式汇合和抽屉滑动保护。
- [ ] W4、W5 分别覆盖紧耦合双手和行走与抓取并行的准入。
- [ ] 每例包含分轨时间线、资源占用、消息序列及三值效果判断。

## 记法

`E` 是只读头部相机，`LA/RA` 是左/右臂，`LH/RH` 是左/右手，`W` 是腰，`L` 是双腿与浮动基座。
`S2` 决策轨、`MON` 事件轨都用于追溯。
每列表示一个逻辑区间，长度可变。边界事件如 `FD@t` 和 `acquired@t` 在相应切换处记录一次。
省略的身体轨处于该本体配置批准的空闲或稳定模式，具体覆盖见各例表。
`DRIVE` 写入要有对应 grant。`DEPEND` 使用 S0 维持状态。`TAKEOVER` 在控制边界原子接管，后续才可写入。
`H(S0)` 使用本设计的分轨口径，表示 S0 持续握持，物件可随臂移动。
具体验证依据来自观测。任务推进要经过 Verifier，S1 终态提供本地控制与取证结果。

| Verifier 检查 | 本文如何判断 |
|---|---|
| 请求受理 | 回查原 invocation，拒绝或未决也能按该尝试记录判断 |
| 执行终止 | 查询原执行终态；另行核对停稳及逐轨处置，停稳故障仍可有 FAILED 终态 |
| 效果成立 | 目标、姿态、支撑、接触等谓词有新鲜证据 |
| 意图满足 | 效果所指实例、目的地和约束与有效目标修订一致 |

时间线用于设计审查，条件和阈值需按设备与场景标定。 [标签与共轭规则](../../therblig-vla/docs/derivations.md) · [协议 v1](../../vla-harness/docs/protocol-v1.md)

## W1 单臂拾放红杯

用户请求把红杯放到架子上。场景绑定红杯 `R`、架上支撑区 `S` 和相邻候选。
本例用站姿右手与 `g1-inspire@3`。S0 在主动获取时先安装 `hand.acquire_slow` 限速，再放行闭合；六路轴向计数与独立物手相对运动共同支持握稳判断。样例未附本机绝对 N 批准记录，成功分支可使用已在本工况验证的相对计数阈值；若任务必须用 N，则须先取得匹配的通道模型和批准记录。视觉／位姿独立核对红杯身份、离桌和支撑。
若任务要求绝对 N，而承载通道未标定、校零失效、接触工况不匹配或读数已饱和，则该物理量证据不足。若只需相对载荷变化且原始基线仍有效，可按已批准的计数判据继续。必需样本缺失或过期且无合格替代路径时，起动前阻塞该分支；持物途中则由 S0 保持并补证。

### 资源锁

| 调用 | 独占写入 | 依赖、共享和退出 |
|---|---|---|
| `locate_candidates`、`resolve_target` | 本例无 | `E` 共享读，返回候选与新鲜观测 |
| `move_unloaded` 接近 | `RA`，如预成形已声明则含 `RH` | 退出时驱动处置为 `RELEASED`。S0 默认伺服维持预抓姿态，下一次抓取申请新的 `DRIVE` grant |
| `acquire_object` | `RA,RH` | `E` 共享读；在主动 grant 下先确认 `hand.acquire_slow` 的闭合速度上限，才放行闭合。握稳后原子交给 `RETENTION(hR)`，限速连续生效 |
| `move_payload` | `RA,W` | 依赖 `hR`，S0 维持 `RH` 和 `L`。臂腰退出按下一步协议处置 |
| `stage_for_next_use` | `RA` | 依赖 `hR`，配置柔顺，取证架面和杯位 |
| `release_to_support` | `RH` 接管后写入。本例启用可选微退并申请 `RA` | 核对支撑、原依赖者静稳，在发放新手部 grant 的同一事务消费 `hR`；结束时记录分离与处置 |
| `move_unloaded` 回撤 | 本例仅 `RA` | 无载荷证据通过后回撤，腰保持此前角度。若要求腰回中立，须另行绑定并取得 `W:DRIVE` |

S0 全程持有平衡与限位。搬运时 `RH` 的动作输出被掩码，握持状态仍用于观测与依赖检查。

### 消息序列

~~~text
User → S2          submit_task("把红杯放到架子上")，目标修订 1
Monitor → S2       头部相机和本体状态，含采集时刻
S2 → S1            持久化后派发 locate_candidates，获取候选
S1 → S2            返回 target_localized 及定位证据。S2 把“红杯”绑定到 R
S2 → S1 → S0       move_unloaded(R 的预抓位)，占 RA
S0 → S1 → S2       实测到达，释放预抓授权。Verifier 确认入口可用
S2 → S1 → S0       acquire_object(R) 申请 RA、RH；S0 安装 hand.acquire_slow 并确认，随后放行低速闭合
S0 → S1 → S2       核对 RH 轴向计数及已批准阈值；确认握稳后原子转 RETENTION(hR)，沿用限速包络
S2 Verifier        用视觉身份、相对运动与载荷佐证核对 R 已受控，杯底此时仍可由桌面支撑
S2 → S1 → S0       move_payload(R,S,hR) 取得 RA/W 新授权，登记 RH 依赖
S0 → S1 → S2       开始提升后验证 R 已离桌，再验证到达架旁区域与授权处置
S2 → S1 → S0       stage_for_next_use，先验证架面与姿态
S2 → S1 → S0       release_to_support 通过 TAKEOVER 接管 RH，测得支撑与脱离
S0 → S1 → S2       released@t，RH 处置 RELEASED，返回测量
S2 → S1 → S0       move_unloaded 回撤。Monitor 送来最新观测
S2 Verifier        最终验证 R 由架面支撑、位于 S、手物已分离
~~~

S2 在每次派发前检查当前目标修订、前驱效果与 S0 处置。
S2 通过 Result 判断是否还需等待。中途出现遮挡时选择取证能力，
主运动只在所需证据可用且已获独立授权时恢复。

### 每步验证分支

| 验证点 | `SUCCESS` | `FAILED` | `UNKNOWN` |
|---|---|---|---|
| `SH/ST` | 唯一实例 `R` 的位置与身份已绑定 | 完整有效视野内证实要求不符 | 颜色混淆或视野缺失，先换视角 |
| `TE` 接近 | 预抓位在窗口内且无非预期接触 | 可靠测量显示偏离或碰到邻物 | 测时或坐标标定不可核对 |
| `G` 获取 | 身份是 R 且已建立稳定控制 | 确认未取得控制或握住邻杯 | 身份或稳定控制证据不足 |
| `TL` 的拾起检查点 | 开始提升后观测到 R 离开原桌面且仍在手中 | 拾起执行结束，相机确证 R 仍留在原桌面 | 桌面遮挡且缺少其他离桌证据 |
| `TL` 到达 | R 稳定进入架旁目标区 | 证实滑移丢失或到达错误区 | 末端姿态可信，但杯的位置不明 |
| `PP` | 姿态达到架面支撑约束 | 角度或间隙确定不满足 | 架边被遮住且其他测量不足 |
| `RL` | `R` 受架面支撑且与手分离 | 确认杯跌落或挂在手上 | 释放反馈已到，支撑与身份暂不可见 |
| `TE` 回撤 | 在清空路径上撤回，杯位随后仍稳定 | 回撤扰动已放好的杯或有碰撞证据 | 末端定位或放置后的杯位未能确认 |

| 预置 | 架面、姿态和支撑域 | 架边遮挡 | 支撑未证实 | 视野不全 | 无 | 观测，Verifier 暂记 UNKNOWN |
| 放手 | 支撑转移、开度和卸载 | 缺独立支撑 | 守卫未满足，S1 不放手 | 杯底不明 | 维持原握持 | 观测、执行与支撑复核 |
| 撤离 | 空手间隙、人员工作区 | 有人进入硬禁区 | 检查实测危险域 | 人员候选 | 硬规则命中才锁存 | 中断、S0 实际范围 |

表中每个调用先推 brief 再派发，存活期间同 ID／同摘要刷新，受理后补 execution_id。普通观测照常发布；所有保护行均先请求 S0，再发 CANCEL_AFFECTED。下文表中“中断”沿用此含义。刷新已含句柄时 affected_execution_ids 列已知执行；若尚未补入则按阶段的 invocation_id 定位，必要时用 D8；无已知执行和阶段的独立基线保护按非空资源范围隔离。S1 的 Execution 和 S0 的 ProtectionReceipt 是独立记录。

取物首发丢失：刷新前只有基线；若发生硬危险，intent_status=UNKNOWN。S2 无法得知丢包。另一分支中简报已到但 S1 已取得授权，宽限从收到简报与手被本阶段占用之较晚者起算。窗口内力流恢复并布防，立即检查当前读数，不向 S2 发送布防消息。若仍缺 right.hand.force，则请求 SOFT_HOLD，再发 monitor/required_clause_unarmed，记录 GRACE_EXPIRED、缺失流与 CANCEL_AFFECTED。此时尚未收到含句柄的刷新，列表为空；S2 按 invocation_id 定位并取消或封住待发调用。只有证据恢复、能力／参数或子句变化，或 GRACE_EXPIRED 的持久重试预算尚可用，才在对账后以新 attempt 重派；预算用尽记 FAILED，无替代方案则请求用户介入。

## W2 错物与用户纠正

初始任务拾放红杯 `R`，旁边还有蓝杯 `B` 和其他邻杯。
Monitor 可独立发现手发散到禁选物，也可识别用户说“不是红杯，是蓝杯”。
错物预警触发保护和复查，用户纠正才改变目标。
以下展示两个信号都发生的序列，也适用于只收到纠正后先停止再重新绑定的场景。

### 分轨 Simo 时间线

| 轨 | 执行旧目标 | 触发保护 | 取消与对账 | 无握持恢复 | 有握持恢复 | 蓝杯重派 |
|---|---|---|---|---|---|---|
| `E` | 旧目标与邻物 | 记录接近/接触 | 查手、桌面及身份 | 确认无接触 | 确认支撑、脱离 | `SH`、`FD@t`，观察 `B` |
| `RA` | `G(R)` | S0 受控停稳 | 姿态保持 | `TE` 回撤 | `TL/PP/RL` 经新调用放回 | `TE/G(B)` |
| `RH` | 旧 grant 闭合目标 | 保持适当开度或已建立接触 | 空手证据或恢复令牌 | 空手 | `H(S0)` → 接管 → `RL` | `G(B)` → `H(S0)` |
| `W/L` | S0 稳定 | S0 按耦合保持 | 状态核对 | S0 稳定 | S0 保持，必要时另行授予腰 | S0 稳定 |
| `LA/LH` | S0 稳定 | 受全身保护时纳入范围 | S0 稳定 | 同前 | 同前 | 同前 |
| `S2` | 修订 1 | 封锁受影响派发 | 取消、查询、核对处置 | 授权回撤 | 授权放回，验明新状态 | 修订 2 绑定 `B`、禁选 `R` |
| `MON` | 按红杯阶段简报检测 | 触发错物/纠正中断 | 关联原始观测 | 观察路径 | 观察放回 | 按新简报检验目标 |

### 消息序列与丢回执

~~~text
S2 → Monitor       派发 iR 前推送修订 1 的目标、禁选与资源子句，阶段内刷新
S2 → S1 → S0       iR / eR 的一块同时使用 RA:11、RH:12，controller_epoch=3
Monitor → S0       错物趋近可先 SLOW，已形成接触或有效纠正时 SOFT_HOLD
Monitor → S2       exec/wrong_target_approach 和/或 user/correction
S0 → Monitor/S2    受影响 grant 失效，保护 3→4；本次未重启，控制代际仍为 3
S2                 受理纠正，目标修订推进至 2，隔离旧派发和旧提交
S2 → S1            cancel(eR, 已持久化的取消幂等键)
S1 → S0            请求停止，若保护已作用则核对停稳与占用
S1 ⇢ S2            取消 RPC 回执丢失，调用方暂标 UNKNOWN
S2 → S1            GET /v1/executions/{id}，查询同一 eR
S1 → S2            核心 GET 内联 S0 所有权和稳定性。Monitor 补充新的世界观测
S2                 STOPPING 继续等；COMPLETED 核对稳定与 E/RA/RH 的完整处置
S2 → S1 → S0       依观测选择新回撤或新放回，重新申请授权
S2 → S1 → S0       派发蓝杯 B，forbidden_targets 包含 R
~~~

对应 JSON 中，`iR` 为 `inv.r1.01`，`eR` 为 `exec.r1.01`，已维持的右手引用为 `retention.17`。
若创建回执也丢失，按原 invocation_id 查 `PENDING / REJECTED / ADMITTED / ABSENT`。有句柄即按原句柄读取；`ABSENT` 在原始 `start_deadline` 已过后须重新读取，确认权威账本覆盖原签发窗口，再核对 `core_evidence` 和世界效果。
取消重投必须带键。同一执行上的合法取消合并，已受理或完成的状态保持其原裁决。`TOO_LATE` 只适用于终态先于首次取消受理。
如果停稳期间故障并取得权威隔离记录，S1 报 `FAILED + ACCEPTED`、`stable=false`，受影响资源继续隔离。超过 `max_quiesce_ms` 时升级保护，此分支不派发回撤或新拾取。
锁存保护逐原因匹配 Monitor 解除与 S0 本地检查。恢复调用在新的授权下执行。

### 资源处置与恢复

| 边界 | `RA` | `RH` | S2 恢复条件 |
|---|---|---|---|
| 活跃旧调用 | 旧 `DRIVE(11)` | 旧 `DRIVE(12)` | 纠正后冻结旧目标派发 |
| 已保护、对账未完 | S0 稳定保持 | S0 按接触状态保持 | 等待静稳与处置。未知或隔离的轨不重用 |
| 无接触 | 旧驱动已归还 | 已释放，证据显示空手 | 用新 `TE` 调用撤回。若接触不明则先取证 |
| 有握持 | 旧驱动已归还或有安全姿态引用 | `MAINTAINED`，持有恢复令牌 | 新 S1 `TL/PP/RL` 或封装放回能力，确认稳定支撑后接管手再释放 |
| 放回完成或回撤完成 | 可经新授权写 | 已证实空手 | 用新观测绑定 `B` 和禁选列表，重新派发 |

恢复操作的退出条件用当前效应验证。在有负载且身份尚未知时，仍可按已授权的安全放回路径验证支撑，
并把旧目标效果记为未知。放手沿能力主路径进行，只有接管后的技能能改变握持。
若无法确认持物身份，选用入口允许“身份未定的已保持载荷”、且当前包络覆盖该载荷的恢复能力。常规搬运的目标身份谓词仍须满足；覆盖范围不明时维持稳定并补证。

### 验证分支

| 结论 | 旧尝试与恢复的证据 |
|---|---|
| `SUCCESS` | 新修订观察到 `B` 在手中并最终由目标架位支撑。旧尝试仅保留审计。 |
| `FAILED` | 接触证据确定握了禁选对象，或新版本已执行提升后相机确证 B 仍留在桌上。 |
| `UNKNOWN` | 静稳已确认，但遮挡使手中物件身份未知。先取证或完成安全恢复，避免提交或盲目重复。 |

### W2 修订围栏

纠正中断携带刷新已知的 eR；阶段未补句柄时按原 iR 定位。S2 发一次 REVOKE 并停刷，撤销先于迟到快照时以高水位挡住首发；撤销丢失时保护 epoch 3→4 也结束旧阶段。取消已确认而恢复简报尚未到达的间隙只有基线，intent_status=UNKNOWN。旧修订的中断不提交新目标；已经施加的软保护仍按 D10 对账。

在同一红杯阶段，Monitor 先处理含 eR、较晚 valid_until 的刷新，再收到尚无 execution_id 的较早快照。保留 eR 与较晚租约，宽限不重置。若此后连续漏收刷新，租约到期时移除红杯子句，转回 BASELINE。同一快照的有效续租抵达，核验签发者、作用域、摘要、代际及资源未释放后重新布防，沿用原宽限历史。对照分支：若 REVOKE 已到，或 S0 保护 epoch 已从 3 推进至 4，迟到的刷新即使带更晚的 valid_until 也被丢弃，旧目标不能复活。

## W3 两臂并行打开抽屉并放入物品

目标是打开抽屉 `D` 并将物品 `I` 放入。左手执行开抽屉的 `Use` 封装技能，右手在独立工作区先接近再获取。
本例配置批准两支在腰中立、双腿保持平衡时并发。
抽屉到位后若固定机构已能保持开度，左手可走安全退出。若仍需扶持，左臂与左手转 S0 保持。
插入前要检测左臂及抽屉的实际扫掠空间。示例采用可兼容右臂和腰运动的扶持姿态。

| `LA` | `U` 开抽屉 | `U` 继续拉开 | S0 姿态保持或退出 | 保持已验证扶持 | 保持或经能力退出 |

### 资源锁

| 阶段 | 左支占用 | 右支占用 | 共享与冲突 |
|---|---|---|---|
| 并发 | `[LA,LH]` DRIVE，保留抽屉扫掠区 | `[RA]` 接近，之后 `[RA,RH]` DRIVE | 两支都共享 `E`，均无独占 `W` |
| 右支先结束 | 左支仍 DRIVE | RA 已释放，默认伺服守住空闲姿态；RH 由 S0 保持 `hI` | RA 等待 B1，记 UD；无臂部前序令牌 |
| 屏障 B1 | 确认开度，S0 返回 `LA:POSE_HOLD(hPose)` 和 `LH:RETENTION(hHandle)` | TL 获新 RA/W DRIVE，RH DEPEND(hI) | S0 登记 `LA:DEPEND(hPose)`、`LH:DEPEND(hHandle)` 与右侧写授权 |
| 摆位与释放 | 两个左侧状态在整个插入期间保持 | PP 的 RH DEPEND；RL 改为 RH TAKEOVER(hI)，微退时另领 RA DRIVE | PP、RL 各自绑定两个左侧 DEPEND；L 的基础 BALANCE 为 MAINTAINED |
| 退出 | 保留 `hPose` 和 `hHandle` 依赖 | 本例 RL 启用 `withdraw` 并持 `RA:DRIVE`，放手后沿受保护路径撤出 | 实测右臂和手已清出扫掠区，才可注销依赖、派发普通 TE 或申请关抽屉 |

`acquire_object` 已为 RA 出具 `RELEASED`。等待期间 S0 的默认伺服不签发臂部接管令牌，B1 后 TL 直接申请新的 `RA:DRIVE`。
若抽屉还需扶持，选择目录中的 `move_payload_guarded_drawer`、`stage_for_next_use_guarded_drawer`、`release_to_support_guarded_drawer`。每张变体都把两项左侧状态作为必需 DEPEND，并按对应身体组合检查右手访问；同一安装图在每个调用内单独核验。普通站姿搬运卡只能用于抽屉自行保持且左支已安全退出的情形。
依赖覆盖整个进入、摆位和离开扫掠区的时间。阶段交接时 S0 先登记后继保护依赖再撤前项，或保留空间驻留保护直到实测清空。本例选带 `withdraw` 的受保护 RL；若原地释放后手臂仍在区内，持续保留扶持，只有另一个已批准且同样绑定两项依赖的撤出调用才可移动。
若左侧请求接管，S0 阻止新依赖，等待右侧完成并退出，或封锁所有右侧依赖 grant、确认实测停稳且新的交接空间安全。一个抽屉开度读数不足以放行。

### 消息序列

~~~text
S2 → S1 → S0       左支 eL: open_drawer(D)，授予 LA、LH
S2 → S1 → S0       右支 eR1: move_unloaded(I)，授予 RA
S2 → S1 → S0       右支 eR2: acquire_object(I)，授予 RA、RH
S1 → S2            右支终止。Verifier 确认 I 在手中，S0 保持 hI
S2                 B1 等左支。右臂为 UD，右手为 H(S0)
S1 → S2            左支返回开度证据、hPose 与 hHandle 的实测处置
S2 Verifier        B1 验证开度、清空、稳定、物品身份及两个左侧令牌
S2 → S1 → S0       TL 新领 RA/W，PP 新领 RA；两者各登记 hPose/hHandle/hI 的 DEPEND
S2 → S1 → S0       RL 保持 hPose/hHandle 的 DEPEND，接管 RH 并原子消费 hI
S1 → S0            RL 的 withdraw 阶段沿受保护路径撤出 RA，两个 DEPEND 持续
S1/Monitor → S2    实测右臂和手清出扫掠区，交还授权；此后普通 TE 可申请新 DRIVE
S2 Verifier        物品位于抽屉内、已和手分离。可按任务决定关闭
~~~

如果抽屉在放入期间滑动，Monitor 直接让 S0 保护耦合范围，并独立向 S2 发中断。
S2 隔离并取消在途调用。旧 grant 失效，S0 尽量维持仍安全的右手负载、左边接触和身体平衡。
核对取消终态、静稳和资源处置之后，重测开度、支撑和路径，决定撤回、稳定抽屉或在新授权下恢复。

### 验证分支

| 结论 | B1 与物理效果 |
|---|---|
| `SUCCESS` | 开度和路径满足进入条件，`I` 身份正确。放下后观察到 `I` 在 `D` 中、已脱手。 |

## W4 簸箕与扫帚

两手分别获取工具。扫帚末端与簸箕入口是连续变化的相对位姿关系，使用一个 `PROVIDER_COMPOSITE` 技能协调。
当前 Resolver 在协调阶段阻止绑定与派发，也不发送该阶段的耦合简报。
这条时间线以未来另行验证的协调身体组合为前提。`g1-inspire@3` 未发布 `LA/RA/W:DRIVE + LH/RH:DEPEND` 的双工具扫动组合，Resolver 对随附档案应阻塞 W4，即使提供者列有扫动模板。
S1 双工具相对位姿闭环的节奏须实测后才能用于该组合。

| 轨 | 获取 | 协调扫入 | 退出 |
|---|---|---|---|
| `LA/RA/W` | 左右臂分别 `G` | 同一能力持有三轨，`U` | 停稳或按能力交接 |
| `LH/RH` | 转交 S0 | `H(S0)` 双手保持 | 保持或在支撑面上经能力接管 |
| `L/E` | BALANCE、观察 | BALANCE、观察相对姿态 | 观察工具与集物区 |
| `S2/MON` | 核对工具 | 周期性验证、监测滑移和人员进入 | 阶段效果验证 |

| 阶段 | 权限 | 检查 |
|---|---|---|
| 工具已持有 | 两手为 S0 `RETENTION` | 两个维持令牌、工具与装载状态 |
| 耦合动作 | `[LA,RA,W]` 一次性独占，`LH/RH` DEPEND | 相对位姿、力限与联合扫掠范围 |

~~~text
S2 → S1 → S0       两次获取，随后一个协调技能申领 LA/RA/W
S1 → S0            统一短块控制两个手臂相对运动
Monitor → S0/S2    出现保护条件时保护整个耦合域并中断
S1/Monitor → S2    接触与集物区证据，进行周期性和终态验证
~~~

`SUCCESS` 为目标清扫物确已进入簸箕，`FAILED` 为确认漏扫、洒落或工具滑移导致效果不成立，
`UNKNOWN` 为遮挡导致工具关系或收集效果无法分辨。

## W5 行走和上肢抓取

随附 `g1-inspire@3` 未批准步态与上肢操作的并发组合。随附搬运卡要求 `L:MAINTAINED` 的站姿，与步态的 `L:DRIVE` 冲突。当前档案应串行：仅在步态取得合格支撑证据时先行走，取得 L 的 RELEASED 回执且站稳后，再抓取／搬运。
下表描述未来动态支撑变体的准入条件。该变体要声明来自步态的动态支撑依赖和失效守卫，配套身体组合须批准该负载、支撑与运动包络，并在失去支撑时同步封锁上肢 grant 和队列。行走的接触估计替代路径也需按变体验证。

| 轨 | 并行阶段 | 抱持或遇障 |
|---|---|---|
| `L` | `LO`，行走策略与 S0 步态跟踪 | S0 在耦合检查后制动、保持平衡 |
| `RA/RH` | `G` 或 `TL`，按授予条件驱动 | 手中物件由 `H(S0)` 保持。必要时同时停臂 |
| `W` | 本例不授予两支独占 | S0 协调姿态 |
| `E/S2/MON` | 观测目标、步态和障碍 | 记录保护与状态，复查目标和授权 |

| 分支 | 资源 | 准入与处置 |
|---|---|---|
| `x.locomote` | `L:DRIVE`，本例不写 W | 步态授权正常结束只给 L 一个 RELEASED；S0 继续平衡 |
| 未来动态支撑上身变体 | 采用获准组合与支撑守卫，搬运示意为 `RA:DRIVE`、`RH:DEPEND` | 步态中止或动态支撑失效即封锁相关上肢运动，S0 继续维持安全握持 |

~~~text
S2 → S1 → S0       提交步态分支与上身分支，S0 原子判定各组兼容
Monitor → S0       障碍进入路径，本地规则对腿轨施加 STOP_LATCHED
S0                 动态支撑失效即封锁上肢依赖授权及排队块，继续安全 RETENTION
Monitor → S2       给出保护范围；核心查询返回现时所有权与各执行的实际处置
~~~

`SUCCESS` 为验证到达与对象持稳，`FAILED` 为明确偏离路径或未获得目标物，
`UNKNOWN` 为失去基座定位或缺少对象身份测量。只有在保持与运动都满足当前包络时才继续下一段。
本例腿轨恢复还须 Monitor 发送解除信号、S0 本地检查通过，并为重新受理的步态调用签发新代际。

实机档案修订 3 的惯性与足接触路径均未就绪；Resolver 阻止行走。若 Monitor 单独收到依赖该路径的测试简报，则是 UNSUPPORTED 或 PENDING_INPUT，不能报告 LOST。

[行走简报](../../vla-harness/contracts/v1/examples/monitoring-brief.locomote.json)沿用修订 3 的资源布局，观测与操作策略来自独立的仿真部署。该夹具的 `sim.walk.support@1` 初始取得 `sim.walk.body.imu` 与 `sim.walk.body.foot_contact` 的有效样本（证据 `sim.walk.support.available`），姿态子句进入 ARMED。随后足接触样本失效（`sim.walk.support.lost`），其余流仍可用；先请求 SLOW，再发[覆盖丢失中断](../../vla-harness/contracts/v1/examples/event.required-clause-coverage-lost.json)，以 inv.walk 定位，处置 CANCEL_AFFECTED。此部署不授予实机支撑资格。

与停稳行分开核对两个基线分支：[行走中租约到期跌倒](../../vla-harness/contracts/v1/examples/event.baseline-fall-unknown-intent.json)发生在行走尚未结束时，意图 UNKNOWN，先前刷新已给出 exec.walk。另在[空闲跌倒](../../vla-harness/contracts/v1/examples/event.baseline-fall-idle.json)中，无已知执行和阶段；硬规则直达 S0，带 CANCEL_AFFECTED 的中断按资源封住重叠待派项，再以 S0 实际保护回执核对所有者和执行。Monitor 重启到首次有效刷新前同样运行基线。并行行走和抓取仍是未来授权用例。

## 对账与回放检查

| 对账记录 | 可复核的断言 |
|---|---|
| 目标修订与 invocation 草案 | 旧修订的迟到结果只供历史追溯，当前提交绑定新目标。 |
| S0 处置与静稳证据 | 停止后的资源能否重用取决于释放或适配的接管，优先处理隔离轨。 |
| 放置与回撤分别验证 | 当前放置效果已证实时，可规划安全回撤并在其后复查，避免重复放置。 |
| 失去视觉或接触证据 | 能确认的控制状态保留，缺失的物理谓词记 UNKNOWN 并记录缺失来源。 |
