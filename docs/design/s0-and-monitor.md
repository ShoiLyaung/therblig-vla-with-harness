# S0 与实时事件监测器

本文定义 G1 + Inspire 本体的控制授权、维持状态以及 Monitor 触发保护的路径。

## 验收清单

- [ ] S0 在策略卡顿、请求超时和停止期间继续维持平衡、限位及仍可安全保持的接触。
- [ ] 每个驱动轴只有一个外部写入授权。运行时能识别过期 grant 并提供交接和静稳证据。
- [ ] S2 直连仅有四类有界模式请求。放手由 S1 能力接管，锁存保护由 Monitor 和 S0 联合解除。
- [ ] Monitor 独立监测用户、本体与环境。保护信号直达 S0，中断及证据独立投递给 S2。
- [ ] 可分别测量检测、投递、稳定三个阶段，并重放保护、取消和资源处置记录。
- [ ] 两种 S0 代码归属方案及各自的验证条件已登记。

## 1. 边界与数据流

S0 拥有设备驱动、本地控制周期、状态测量与最终控制权。
S1 面向已委托的子任务，输出有有效窗口的局部控制目标。
S2 按事件或任务需要运行，通过能力接口协调与验证结果。
Monitor 在三层之外按各输入的采样节奏观察。命中规则则主动发出信号。

~~~text
S2 ── Invocation ──→ S1 ── grant + 有效控制目标 ──→ S0 ──→ 本体
S2 ←── Result ────── S1 ←── 实测状态、授权处置 ─── S0 ←── 传感器
S2 ── 可选 ModeRequest ─────────────────────────→ S0
S2 ←── 观测或带 interrupt 的 Event ──────────────────────── Monitor
S0 ←── 即时保护信号 ──────────────────────────── Monitor
Monitor ←── 用户、身体遥测、物理世界观测
Monitor ←── S2 单向阶段简报／刷新／结束
~~~

控制目标只在通过 S0 的校验后进入伺服。S0 在同一局部控制时基上处理限位、目标过期、保护和执行器命令。
模式请求的服务进程、遥测序列化和 S2 模型推理都在伺服周期之外。
Monitor 的规则确定触发条件、保护级别和建议范围，S0 根据本体状态与耦合扩大实际保护范围。

架构与跨仓边界以总仓约束为准。运行频率分层验证。 [总仓 README](../../README.md) · [参考架构 Fig. 3](https://arxiv.org/html/2611.18359v1#S2.F3)

## 2. BodyProfile 与本地控制

### 2.1 G1 + Inspire 轨道

| 轨道 | 本体对象 | 驱动与兼容约束 |
|---|---|---|
| `E` | 头部相机 | 只读。无主动颈部，换视野需要另外的 `W` 或 `L` 授权。 |
| `LA` / `RA` | 左右臂，各 7 个自由度 | 各有轴映射与工作空间。同一身体上的分支仍受碰撞和动态耦合限制。 |
| `LH` / `RH` | 左右手，各 6 个驱动器 | 分别登记执行器映射、负载能力和已安装的感知。 |
| `W` | 腰，3 个自由度 | 换视角和姿态控制都可能争用。可与平衡控制耦合。 |
| `L` | 双腿与浮动基座，12 个腿部自由度 | 基座位姿为测量与估计状态。步态和全身稳定由 S0 在同一控制边界内协调。 |

`BodyProfile.profile_revision` 固定资源 ID、轴映射、传感器、耦合域、安全限值和可选择的模式配置。
同一资源可被不同能力通过角色名引用，S0 在查冲突前展开为实际轴和耦合域。
末端执行器的 `parent_resource_id` 引用同一修订的承载臂。准入器先验证每次调用的 mounted_on 角色关系，再检查各调用实际绑定和访问的组合。
观测共享不代表视角可同时满足两个分支。随着相机载体变化，Resolver 要重新检查两分支还能获得的视图。

单手保持与对侧运动只在固定站姿、扫掠空间和负载适配时并发。
左右臂均需要主动驱动腰时，应串行调度，或使用一个持有两臂与腰的协调能力。
轨道 ID 是本体配置中的数据，独立本体可发布不同的映射和兼容组合。

每手的六个压力传感器位于微型伺服电缸尾部，感受连杆传递的轴向载荷。`g1-inspire@3` 按 `axis_id` 记录 `FORCE_ACT(0..5)` 的 0–1000 原始计数、标定修订和饱和位。手指表面没有传感器，接触位置影响计数，不能由此定位。DF 系列手册与具体单元的对应仍须核实，2026-09 英文手册链接不可达，未读。[硬件依据与实测来源](README.md#rh56-手部传感依据)
`GESTURE_FORCE_CLB` 在空载且各指无接触时运行约 6 s，建立设备零点。计数换算 N 还需适用于该通道和工况的独立模型。`CURRENT(0..5)` 是独立电流读数，仅在验证后作候补代理。

### 2.2 维持模式

| 模式类 | 主要范围 | 持有内容与退出条件 |
|---|---|---|
| `RETENTION` | `LH` / `RH` | 从已握稳的主动获取阶段接收负载、阈值及有效限速包络，连续维持握持。回读的 N 阈值逐通道核验工况批准；其余只使用获准的相对计数守卫。`CURRENT_LIMIT` 保持独立。 |
| `POSE_HOLD` | `LA` / `RA` / `W` | 短时保持已测姿态或接触关系。下一步接管需满足姿态和力条件。 |
| `BALANCE` | `L` 和必要的 `W` 耦合 | 随支撑接触、载荷和上身运动维持全身稳定。在站立与步态跟踪期间持续。 |
| `COMPLIANCE` | 上肢、手 | 在装备支持的条件下以阻抗或导纳等本体配置执行局部目标。受力限、速度和工作空间共同约束。 |
| `LOCOMOTION_TRACKING` | `L` | 跟踪已受理的步态或基座速度目标。支撑条件变化触发局部兜底。 |
| `PROTECTIVE` | 受影响轨或耦合域 | 应用 `SLOW`、`SOFT_HOLD` 或 `STOP_LATCHED`，同步发布实测结果与保护代际。 |
| `REST` | 相关关节或全身 | 在无冲突载荷、稳定支撑和已验证配置下保持低功耗或阻尼姿态。 |

`BALANCE` 是持续的控制职责。步态调用结束时 `L:DRIVE` 只产生一次 `RELEASED`，可选腰部在实际取得时分别结账。S0 的支撑和平衡随后继续运行。
主动获取由 S1 使用本体的局部 `hand.acquire_slow` profile（`COMPLIANCE`、仅本地控制路径）。S0 在签发／激活获取 grant 的仲裁边界安装经现场验证的闭合速度上限，确认限速已生效后才放行第一条闭合命令。在预计首次接触前和整个接触阶段持续限速；未装载有效包络则不放行闭合。握稳后 S0 原子交接给 `hand.retain`，限速与过流保护跨交接连续有效，过期的快速动作块失去写权。
S0 对每个绝对 N 阈值从当前通道模型解析 `validation_record_ref`。它核对签发与有效状态、真实单元、手资源、传感器／通道、轴、校零／模型修订、接触工况与阈值范围；使用代理时还核对相应代理 profile 修订和批准用途。使用本地缓存的有效记录，有变更则重验。无匹配记录或模型为 `UNCALIBRATED` 时不装载 N 阈值。`FORCE_SET` 只写经核验的设备设置码。
高速初触会产生力超调。S0 分别记录 `STATUS(m)` 的 3（力控到位）、5（电流保护）和 6（堵转）。握稳与滑移需要物手相对运动佐证。满码、样本过期或工况不匹配时进入适用的安全保持并补证。
`COMPLIANCE` 可在获准范围内调节接触，维持期限到达时重新评估负载和稳定性。释放物件仍由 S1 能力显式接管。

例如，右手在获取后交给 S0 的 `RETENTION`，右臂随后在独立 grant 下搬运动作。
左手可同时工作，前提是站姿、扫掠体积和视野都在兼容边界内。
搬运终止后若要放到支撑面，由匹配的 S1 能力先验证支撑，然后接管握持轨完成放手。

### 2.3 S0 输出

| 数据 | 主要消费者 | 用途 |
|---|---|---|
| 各轨所有者、模式、grant 代际、处置 | S1、S2 | 核对权限、接管、对账与任务恢复 |
| 关节和手的实测位置、速度、驱动健康 | S1、Monitor | 跟踪、失联与设备故障检测 |
| 基座位姿、支撑接触、稳定性指标 | S1、Monitor | 动态准入和保护范围 |
| 手开度、接触、滑移、负载及其可信度 | S1、Monitor、Verifier | 维持、效果取证与安全退出 |
| 保护级别、范围、保护 epoch、控制器 epoch | S1、S2、Monitor | 限制过时授权、恢复与归因 |
| 静稳证据、传感器健康、时钟来源 | S2、Monitor | 区分控制已停止与物理效果仍未知 |

S0 区分当前身体快照与不可变的执行收口账本。前者发布两个 epoch、boot_fenced、每轨所有者、活动 grant、依赖者、保护原因和实测稳定性。S1 经必选 `core-execution` 的执行与调用查询返回 `core_evidence`；可选 `GET /v1/body/state` 读取同一权威状态。读取失联或证据过期时继续隔离。
收口账本关联 body、execution、S0 启动实例、时间、各资源历次 grant 及最终 owner／代际。空间测量附参考系、单位及标定。S2 另据新世界观测验收物理效果。

## 3. 仲裁、交接与故障

### 3.1 访问方式与裁决

| 访问 | 准入 | 权限变化 |
|---|---|---|
| `OBSERVE` | 身份与观测范围允许 | 共享读，保持既有控制权限 |
| `DRIVE` | 写轴和耦合域可用，模式与约束相容 | 独占写，获得有界 grant |
| `MAINTAINED` | 背景控制独立于前序调用，如身体平衡 | S0 维持；前一步保证的姿态或持物须通过令牌依赖 |
| `DEPEND` | 注册当前令牌、其消费者 execution 和该执行依赖它的写 grant | S0 持有，依赖持续检查，并可级联隔离 |
| `TAKEOVER` | 验明令牌、支撑和姿态连续，关闭新依赖登记 | 确认所有冲突依赖者已结束或已被封锁且实测停稳，再原子消费旧令牌并授予写权 |

保护优先，经 S0 准入的维持态次之，常规 S1 目标最后。
接管在同一仲裁边界登记意图并阻止新的冲突消费者。等待现有消费者安全退出，或封锁其已发及已排队目标，核实受影响身体静稳；依赖者处于未知或所在工作区尚未清空时继续维持原状态。随后合并消费令牌、签发新 grant、启动新控制选择器三步。
S1 的每个块含 `execution_id, body_id, controller_epoch, sequence`，并携带覆盖所有写轴的 `grants[{resource_id, grant_generation}]`。S0 在实际消费前同时校验完整资源集合、每个 generation、时窗、依赖和单调序号；任一不符丢弃整块。

`controller_epoch` 与 `protection_epoch` 在重启及每次全身授权重置时一起推进到各自持久高水位之后，再允许新的仲裁。S0 在预留、激活和实际应用模式时分别比较请求冻结的 `expected_protection_epoch`；旧值即使尚在原截止窗口内也拒绝。局部保护触发或解除只推进保护版本并隔离相应轨的 generation。样例为局部保护，控制实例为 3，保护从 3 推进到 4。
`Execution.leases` 携带控制代号；Invocation 和 ModeRequest 校验保护代号，ProtectionReceipt 回报保护代号。核心只读快照、Result.quiescence、ModeStatus 及可选本体状态同时发布两值。

### 3.2 维持态跨调用

~~~text
执行结束前：
  S1 仍持有驱动 grant
  S0 测得握持或姿态达到所声明的交接条件

同一控制边界：
  S0 接管维持、使旧写授权失效、记录状态代际
  S1 获得该轨的 MAINTAINED 处置与维持引用

后继：
  DEPEND → 登记依赖执行和写授权，实时检查令牌
  TAKEOVER → 封闭新依赖、等既有依赖结束或封锁且实测停稳，再切换写权
~~~

S0 发出的维持引用限定身体、资源、状态代际和可用的后继形态。
引用依赖的接触或姿态失效时，S0 通知相关执行并在本地保护。
新调用需要相同写轴时，选择已经释放的轨，或执行有证据的接管。
等待屏障期间可以保留一个合格的维持状态，例如左臂维持抽屉姿态与右手保持物件。

### 3.3 停止、超时和恢复

1. 保护、块过期、命令失联或执行结束时，S0 撤销受影响 grant，并使依赖该状态的动作块整体失效。
2. 取消受理时启动本地停稳看门狗，维持安全支撑与握持。到 `max_quiesce_ms` 仍无稳定证明即升级保护并告警。S1 断线或提前发布故障终态不会撤销该看门狗。
3. 对每个历史取得的资源给出唯一处置，关联不可变 S0 账本、历史授权和最终 owner。转移必须标明接收方及新代际。
4. 已获准取消后发生故障，可记 `FAILED + ACCEPTED`。S0 如实记录是否已激活和每项历史访问是否结清；仅未结清项记 `QUARANTINED`。整体 `stable=false` 时取消保持受理。独立恢复后，S0 经核心查询签发绑定故障执行、原记录和已清除资源的回执。
5. S2 用核心查询读取当前所有权与实测，再刷新世界证据并决定是否重新受理。

`RELEASED` 表示相应调用已归还授权，S0 仍负责伺服本体。
`QUARANTINED` 表示占用或可达安全状态尚需恢复，普通冲突调用等待对账。
断网、超时、丢回执与配置变化的可见性和效果判断分别记录。
无法确认安全交接时，保持保护并阻止受影响范围内的新授权。

## 4. 有界 ModeRequest

S2 经 Tool Interface 调用 S0 提供的可选 `body-modes` profile。
S0 先认证、比较冻结摘要并查原键；重复请求直接返回原状态。首次请求以 `issued_at` 和同一时钟域的绝对 `start_deadline` 固定最迟切入时刻，重投和排队都不重置窗口。
本体档案以 `allowed_verbs` 明确各 profile 的可用动词；空表仅供本地路径。未指定 profile 的动词也须经批准的默认映射。

| `mode` | 许可效果 | 例子 |
|---|---|---|
| `HOLD` | 在限定范围和时长内维持已存在的稳定状态 | 保持腕臂姿态，以便重新取证 |
| `SLOW` | 在批准的配置下施加更严格的速度或运动包络 | 观察期间对在途运动限速 |
| `STOP` | 停止指定范围内现有运动，进入批准的安全姿态 | 用户取消任务后停止相关分支 |
| `SWITCH_PROFILE` | 切换到白名单中的本体模式配置 | 满足空载和支撑条件后进入 `REST` |

受理检查依次覆盖以下条件。

1. 验证调用方身份，按身体、动词、`scope` 和 `profile_id` 授权。
2. 依据 `profile_revision` 校验作用范围、`bounded_params`、时限和约束。参数取值服从已配置的局部包络。
3. 在实际切入的控制周期，将请求冻结的 `expected_protection_epoch` 与当前值比较，同时核对全部依赖与实测。全身重置造成代际不符、或时钟换算无法证明早于原始截止，均拒绝切入。
4. 安装、取代和到期时重新校验有效的动词/profile 白名单、继承的保护、`RETENTION` 和支撑条件。即使配置名合法，只要会削弱保护或打开持物手就拒绝该切换，维持 S0 的安全状态。

~~~text
REQUESTED → ACCEPTED → APPLIED → EXPIRED | SUPERSEDED
REQUESTED → REJECTED
~~~

`REQUESTED` 可排队。S0 在同一个本地控制周期裁决保护与模式切入，保护先赢时直接给原请求 `REJECTED`。
普通请求胜出时，在同一次选择器切换中记录 `ACCEPTED` 和 `APPLIED`，并采样实际范围及 `measured_state_ref`。紧随其后的更高保护可将该模式置为 `SUPERSEDED`。
切入模式与身体停稳有各自的证据。若回执丢失或控制器重启，按原 request_id、控制代际与实测对账；未确认稳定的冲突作用域继续隔离。
到期时由 S0 选择局部兜底，旧数据块的写权限仍然失效。
握持的建立与解除走 S1 主路径。接口白名单拒绝开爪、原始关节目标、任意控制配置及清除 `STOP_LATCHED`。
同幂等键与相同请求摘要读取同一状态，摘要变化返回冲突。

## 5. Monitor 输入、规则与信号

### 5.1 输入与阶段简报

| 来源 | 可用证据与限制 |
|---|---|
| 本体内感受 | 关节与手指位置、各手六路专用轴向计数及独立电流。IMU、关节力矩估计、驱动温度分别建流，安装坐标、单位或适用工况待验证。底层状态消息没有足底力；足接触是待验证的模型估计。 |
| 外感受 | 头部视觉、深度、点云与语音。产品资料声明深度相机、激光雷达和麦克风阵列；具体型号、坐标及部署可用性单独核验。腕部相机未确认。 |
| 控制状态 | S0 的当前模式、grant、稳定性、保护原因、scope 和 epoch。它们反映身体内部状态，流类型为 CONTROL_STATE，由控制器发布。 |
| 阶段意图 | S2 在每个可派发阶段开始时单向推送租约简报，随后派发，不等待；并行作用域分别刷新。任务记忆不进入 Monitor。 |

[输入描述与样本头](../../vla-harness/contracts/v1/schemas/observation-stream.schema.json)以采集时钟、帧或编码、来源、有效／饱和位及来源修订解释样本。sensor_ref 指向 BodyProfile 的测量方法、通道、速率、标定及验证状态。速率和时延未测时为 UNSPECIFIED，不填值。实测时延记录起止端、时钟、统计量、工况和来源。另见[本体档案](../../vla-harness/contracts/v1/examples/body-profile.g1-inspire.json)。

子句只收紧当前批准域，聚合采用允许范围取交、禁选取并、上限取小、下限取大、证据取合取。首次简报出现单位或坐标不可比、交集为空时，S2 在发送前查出则 BLOCKED；Monitor 收到后查出则子句 REJECTED，必需项立即请求收紧并发中断。只有在途替换有前任：不能证明为前任子集时拒绝替换，保留仍有效的前任。登记引用固定两端部署的参数 schema、评估器及最高级别；命名空间扩展须预登记。阶段结束发一次 END／REVOKE 并停刷；资源占用后释放、epoch 越过、取代、END、REVOKE 或 FENCED 是终止围栏。租约到期只撤下本阶段子句并回到 BASELINE。同 ID 同摘要的有效刷新可经身份、作用域、写者及保护代际、无释放和无终止围栏核验后重新安装，保留原宽限历史。重装先检查必需子句是否从未布防且原宽限已届满：即使输入已经恢复，也立即判 GRACE_EXPIRED，先收紧再发 monitor/required_clause_unarmed。其余子句按当前合格证据布防；曾布防而缺输入时判 LOST，必需项先收紧再发 monitor/clause_coverage_lost。无刷新时覆盖空窗静默，基线危险仍可触发。

到期记录按部署策略保留。回收时同步推进按签发域保存、只在本次启动内有效的水位（重启时清空），严格越过回收记录的 issued_at；无匹配记录且 issued_at 早于水位的投递一律丢弃。Monitor 重启记本地启动时刻，不持久化 END／REVOKE 围栏。启动围栏仅对 MonitoringBrief 首发和刷新检查映射到本地的 sent_at，早于启动时刻减跨域时钟误差上界时丢弃。无可用时钟映射时只运行基线。END／REVOKE 不受启动时间围栏约束，认证及 brief_id、作用域、摘要和 command_seq 检查限定它只能结束所绑定的单一阶段。重启后的新鲜刷新通过本次水位和控制状态检查，即可重新安装仍存活的阶段，并建立新的本地布防历史。完整字段和状态机见[阶段简报契约](../../vla-harness/docs/protocol-v1.md#51-阶段简报与合同边界)。

必需子句的宽限起点取收到简报与受管资源“被本阶段占用”的较晚时刻，DRIVE、TAKEOVER、DEPEND、MAINTAINED 均算占用。只读阶段没有必需子句。宽限只按批准策略引用计时，刷新不重置。确定无法布防立即按 on_coverage_loss 收紧，宽限到期仍未就绪同样处理；收紧请求先送 S0，再以 CANCEL_AFFECTED 中断。窗口内成功只记本地。可选子句失败及未影响必需覆盖的降级均只记本地。Monitor 不主动访问 S2。

### 5.2 规则表与语义证据

| 条件 | 依赖与证据 | 上限及处置 |
|---|---|---|
| 错物趋近 | 身份子句；新鲜外观与实际趋向、排除实体的几何关系 | SLOW；附目标、发现与轨迹。 |
| 接触错物 | 身份与接触子句；身份与独立接触起始证据 | SOFT_HOLD，保持安全接触。 |
| 用户纠正或停止词 | 语音始终监听；认证纠正须匹配现行指令。确定性停止词不依赖 brief | 纠正 SOFT_HOLD；停止词可 STOP_LATCHED。原话先作为观测入流。 |
| 滑移／掉落 | 载荷子句、指位、非预期卸载与独立相对运动／分离证据；排除预期放手 | SOFT_HOLD，保留仍安全的 RETENTION；单独力下降只支持疑似失载。 |
| 碰撞、失稳、危险区域闯入 | 基线；独立合格的几何、惯性、支撑或身体残差证据。无简报或 VLM 时照常判断 | STOP_LATCHED；S0 按实际耦合扩大作用域。 |
| 健康或限位异常 | 基线；过流、过温、电量、驱动状态及已批准的持续条件 | 依规则从 SLOW 到 STOP_LATCHED，记录来源和实测序列。 |
| 停滞／屏障超时 | 进度子句与实测时间、阻塞原因 | 需复核时 REEVALUATE，无保护请求；独立证实卡滞且需收紧时可 SOFT_HOLD。 |
| 必需子句失败 | 确定不可布防、宽限到期或已布防后失去覆盖 | SLOW 或 SOFT_HOLD，由卡片绑定批准策略。中断写明阶段、子句、失败类型及缺失流。 |

任何伴保护的中断均为 CANCEL_AFFECTED。各原因单独记账，同一资源取最高级别。硬规则直接送 S0。语义层只产出有时限、有来源和置信度的发现：规则层检查类型、检测器、修订、时钟、新鲜度、范围及意图后，才按批准策略评估。受影响运动正在进行、达到准入置信度且多个新样本持续或有独立佐证，可触发 SLOW。SOFT_HOLD 另需安全保持路径和跨模态正向确认或认证纠正；仅视觉可辨的溢出／变形可按逐项批准策略接受不同新样本的一致性。重复描述同一帧只算一次。语义层不能锁存、解除或降低保护。

传输去重按发布者三元组；危险按身体、规则修订、原因、规范化作用域、对象对及 episode 合并，保留证据，同一 episode 最多升级一次。进入、退出、驻留和新鲜度阈值引用本地批准策略。语义超时不参与控制；允许的替代路径仍有效时继续评估，否则必需子句 LOST 先收紧再中断，可选子句只记本地。

力证据必须匹配绑定手、通道、标定及工况：未标定的小指、无名指、拇指旋转只比较相对空载基线的计数；食指、中指与拇指弯曲的第三方拟合也须核验本机批准记录后才可用 N。电流仅为经独立验证的代理。轴向信号不能定位接触。递物须先经已批准的近人 profile 和 SWITCH_PROFILE，由 S0 核验受理且 Monitor 采用同版规则；brief 在该域内缩小范围、添加支撑转移守卫。放手仍由 S1 接管，当前本体未授权近人操作。

缺少语义证据不能证明危险已解除、当前意图成立、支撑已转移或任务已成功。

### 5.3 三档保护及解除

| 级别 | S0 处理 | 后续准入 |
|---|---|---|
| `SLOW` | 限制受影响范围内的运动包络并推进保护代际 | S2 完成取消或状态对账，S0 接受满足当前约束的新授权 |
| `SOFT_HOLD` | 进入可稳定的停止或保持，保留仍安全的负载和支撑 | 对账完成后使用新派发取代，S0 重新判断接触与环境 |
| `STOP_LATCHED` | 锁存作用范围，拒绝恢复运动的旧授权和常规新请求 | Monitor 发出与当前保护关联的解除信号，S0 检查现场与本体条件后才清除 |

S0 按原因持久化所有未解除保护的级别及实际作用范围。每个 `STOP_LATCHED` 分别需要 Monitor 认证的匹配解除（身体、protection_id、原因引用和当前保护版本），再由 S0 本地检查现场、本体和接触条件。一个解除仅结清对应原因；重叠锁存继续生效。
本地保护先行制动，同时通过持久保护记录和失效安全联锁保证断电窗口不会被解释为无保护。启动默认封锁运动。恢复未决原因、范围、保护高水位与旧授权日志，分配不复用的新 epoch，并核实实测和失效授权后才开放相应作用域。
存储缺页、原因不全、高水位无法证明或来源失联时，保持 `boot_fenced=true` 并扩大至必要身体范围；普通模式切换或新 S1 进程均无解除权。仅在匹配解除且本地条件成立时撤下该锁存。恢复运动还需新的 grant。
到期回退也须保留未解除保护、`RETENTION` 与平衡，避免在应用旧默认姿态时掉物。

### 5.4 保护与事件独立投递

~~~text
Monitor 检测规则命中
  → S0 本地保护通道：事件引用、级别、范围、来源、采集时间
  → S2 事件通道：Event + Interrupt、证据引用、受影响调用
S0 作用：
  → ProtectionReceipt：S0 的 producer{id,boot_id,sequence}、原因引用、实际级别、非空资源、应用时刻、保护代际
  → 实测状态：可按证据引用查到稳定、异常和轨占用信息
~~~

先发出本地收紧请求，再发布中断；两路的送达彼此独立。S2 可能先看到事件，再看到保护回执。
S0 根据本地消息应用保护，Monitor 无须等待 S2 的确认。
S2 据事件封锁受影响的派发，再通过回执、Execution 与 S0 实测对账。
保护回执按照 `event_ref` 与事件关联，回执的应用时刻与达到实测稳定的时刻分别记录。

派生世界观测（含所有话语）与 Event 共用同一持久序列，先发布被引用的观测；连续传感引用沿用原机制。Monitor 给 S2 只送观测数据和带 interrupt 的 Event。S0 回执独立按序发布。事件与 S0 回执各按 `(producer.id, boot_id, sequence)` 去重。游标只推进到连续且已持久处理的序号。缺序先按原发布者补放；安全信号的本地施加独立于补放进度。
安全队列与高频常规遥测分开，重复事件不会重复触发一次已应用的状态转换。
检测进程重启使用新的实例代号，旧实例的清除信号和游标不改变当前保护。
Monitor 丢失心跳或传感器失效时，S0 继续本地控制。有保护依赖的运动由身体配置按能力下降处理。
向 S2 的事件传输待在 SSE、WebSocket、DDS 桥之间选定。S0 本地通道独立选择适配实现。

### 5.5 断线恢复与状态核对

Monitor 复连时先读取本体当前保护、控制器实例和本地未结事件。
可补放时，S2 按旧游标连续处理缺失序号。缺口已过保留期时，保留旧游标与缺失范围，冻结受影响任务／作用域的派发，单独建立 `resync_checkpoint`，记录发布者实例、新保留段基线与证据引用。保护快路径继续工作。
例如漏掉“不是红杯，是蓝杯”，身体和调用快照可证实旧动作已停，却无法确定用户现在要哪只杯。S2 从权威输入记录找回纠正，或请用户重新确认当前目标；再处理新保留段的事件、对账在途调用，按有效目标修订持久提交检查点，才恢复相应派发。无法核实意图时保持封锁。
游标回放用于恢复记录，无法替代本地保护的即时投递。

| 看到的记录 | 使用方法 |
|---|---|
| Event 已到，ProtectionReceipt 暂缺 | S2 立即隔离相关分支并查 S0 状态。未确认的轨仍受限。 |
| ProtectionReceipt 已到，Event 详情缺失 | 依据真实保护范围隔离派发，补取事件上下文。 |
| Event 与 S0 状态有冲突 | S0 当前 epoch 与实测决定写权限。保留事件证据，按当前状态重新验证物理效果。 |

## 6. 时序测量与故障场景

| 时点 | 定义 | 证据 |
|---|---|---|
| `t_observed` | 触发条件首次可观测或仿真真值出现 | 输入采集时钟、真值或对照标记 |
| `t_detected` | Monitor 完成规则判定并产生信号 | 规则实例、观测引用、处理时钟 |
| `t_received` | S0 接收并校验保护信号 | 控制器实例、信号序号 |
| `t_applied` | S0 应用保护并更新代际 | ProtectionReceipt |
| `t_stable` | 达到规定的实测停止或稳定保持条件 | 速度、接触、平衡与状态证据 |

厂商刷新率为 `UNSPECIFIED`。按 Correll 实验室的第三方参考观测，其接口读写循环为 163 Hz，命令发出至首次传感回读约 66 ms。两者均来自该组阶跃实验，不能用作本机更新率、最坏时延或保护预算。[Correll 实验室，第 II 节](https://arxiv.org/html/2603.08988v1#S2)
本机在确定滑移、掉落或停止预算前，要用独立时基测量输入变化、通道更新、命令回读和保护动作，记录抖动、重读与丢样。比较逐指空载噪声、标定适用区间和高速超调；接触动作采用经本机验证的低速包络。
有实测依据后报告检测 `t_detected - t_observed`、投递 `t_received - t_detected`、稳定 `t_stable - t_received`。用 `t_applied` 区分控制排队与稳定时间，并给出跨时钟域误差、分位数、漏报和误报。S2 接收事件的时延另计。

| 故障注入情形 | 期望证据 |
|---|---|
| S2 停在模型调用，Monitor 检测碰撞 | S0 仍收到保护并有作用与稳定证据，后续 S2 恢复对账 |
| S1 发送旧 generation 的块 | S0 拒绝旧写授权，维持现有稳定控制 |
| 取消 RPC 响应丢失 | 按句柄取回最新处置，带负载轨仍由 S0 持有 |
| 切换模式与抬高保护同时到达 | S0 优先应用保护，模式回执反映实际状态 |
| 接触传感器不可用或相机遮挡 | 可用局部限值仍生效，Verifier 按足够证据给三值结果 |
| 抽屉进入右手运动空间或步态失稳 | 扩大到关联范围，阻断后来目标并保留可安全保持的握持 |
